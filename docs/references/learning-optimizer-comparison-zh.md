# 学习型查询优化器对比：NeuSO vs Neo、Bao 和 Lero

**报告日期：** 2026-05-06  
**背景：** 为 DuckDB 中 ADL-OPT 开发提供对比分析

---

## 执行摘要

本报告对比了四个学习型查询优化器：**NeuSO**、**Neo**、**Bao** 和 **Lero**。Neo、Bao 和 Lero 针对关系数据库查询优化，而 NeuSO 解决图数据库中的子图查询优化问题。每个优化器在应用机器学习到查询优化时采用了根本不同的方法。

**核心区别：**
- **Neo**：用深度强化学习完全替代优化器
- **Bao**：使用学习到的提示引导现有优化器（基于多臂老虎机）
- **Lero**：使用成对比较对计划进行排序，而不是预测代价
- **NeuSO**：优化图数据库中的子图匹配顺序

---

## 1. Neo：神经优化器 (VLDB 2019)

### 核心方法
Neo 使用**深度强化学习**完全替代传统查询优化器。它学习使用神经网络从头生成查询执行计划。

### 学习方法
- **技术**：深度强化学习与值迭代
- **架构**：树卷积神经网络
- **训练**：从现有优化器（如 PostgreSQL）引导启动，然后从传入的查询中持续学习

### 输入表示
- 通过树卷积编码查询结构
- 处理查询树以提取结构特征

### 输出/决策
- 生成完整的查询执行计划
- 直接产生连接顺序和算子选择

### 训练数据
- 从成功和失败中学习
- 持续适应传入的查询工作负载
- 从现有优化器决策引导初始模型

### 关键创新
1. **完全替代策略**：不依赖传统优化器组件
2. **持续学习**：适应数据特征和工作负载变化
3. **引导启动**：从现有优化器知识开始，而不是随机初始化
4. **鲁棒性**：比传统优化器更好地处理基数估计错误

### 局限性
- 需要大量训练数据
- 完全替代意味着失去数十年的优化器工程积累
- 可能难以处理训练期间未见过的新查询模式

---

## 2. Bao：Bandit 优化器 (SIGMOD 2021)

### 核心方法
Bao 通过提供每个查询的优化提示来**引导现有优化器**，而不是替代它们。它将提示选择视为多臂老虎机问题。

### 学习方法
- **技术**：Thompson 采样（老虎机的强化学习）
- **架构**：树卷积神经网络 + Thompson 采样
- **训练**：从查询执行反馈中在线学习

### 输入表示
- 通过树卷积神经网络编码查询结构
- 处理查询计划以提取特征

### 输出/决策
- 选择**优化提示**来引导现有优化器
- 示例：连接方法偏好、扫描策略、并行度设置
- 不直接生成计划

### 训练数据
- 从实际查询执行结果中学习
- 观察哪些提示导致更好的性能
- 适应不断变化的工作负载、数据和模式

### 关键创新
1. **基于提示的引导**：利用现有优化器的智慧同时学习改进
2. **Thompson 采样**：平衡探索（尝试新提示）与利用（使用已验证的提示）
3. **快速学习**：学习速度"比以前的方法快一个数量级"
4. **非侵入式**：适用于任何接受提示的现有优化器
5. **持续适应**：自动调整以适应工作负载和数据变化

### 优势
- 保留数十年的优化器工程积累
- 比完全替代方法学习更快
- 优雅降级：如果提示不佳，优化器回退到默认行为
- 实用部署：对现有系统的改动最小

---

## 3. Lero：Learning-to-Rank 优化器 (VLDB 2023)

### 核心方法
Lero 使用 **learning-to-rank** 方法，训练一个二元分类器来比较查询计划对，而不是预测绝对代价。

### 学习方法
- **技术**：带成对比较的监督学习（learning-to-rank）
- **架构**：用于计划比较的二元分类器
- **训练**：从带有相对性能标签的计划对中学习

### 输入表示
- 从查询执行计划中提取计划特征
- 编码计划结构和算子选择

### 输出/决策
- **成对比较**：给定两个计划，预测哪个更好
- 不预测绝对执行时间或代价
- 按相对质量对候选计划进行排序

### 训练数据
- 带有相对性能标签的执行计划对
- 学习序数关系："计划 A 比计划 B 好"
- 比回归（预测精确代价）更容易的训练任务

### 关键创新
1. **成对排序**：从回归（代价预测）转向分类（相对比较）
2. **更简单的学习任务**：二元分类比代价回归更容易且更准确
3. **非侵入式设计**：与现有优化器集成（在 PostgreSQL 上演示）
4. **对估计错误鲁棒**：相对排序比绝对代价预测更稳定

### 优势
- 避免了准确代价预测的困难
- 对基数估计错误更鲁棒
- 更容易训练且准确度更高
- 在 PostgreSQL 上报告执行时间减少高达 70%

### 关键洞察
"计划的相对顺序或排名，而不是精确的代价或延迟，对于查询优化就足够了。" 这一基本观察显著简化了学习问题。

## 4. NeuSO：子图查询神经优化器 (SIGMOD 2026)

### 核心方法
NeuSO 优化图数据库中的**子图匹配顺序**。它预测子查询的基数和代价，然后使用自顶向下的枚举器生成高效的匹配顺序。

### 学习方法
- **技术**：多任务监督学习
- **架构**：查询图编码器 + 多任务估计器 + 自顶向下枚举器
- **训练**：联合学习基数和代价估计

### 输入表示
- **查询图编码器**：处理图查询结构
- 处理异构图模式和大量连接
- 专为图数据库特性设计（而非关系表）

### 输出/决策
预测三个关键指标：
1. **子查询基数**：中间结果的数量
2. **执行代价**：执行子查询的代价
3. **最小代价**：从给定状态可达到的最优代价

使用预测来引导**自顶向下的计划枚举器**，生成顶点匹配顺序。

### 训练数据
- 带有基数和代价标签的子图查询
- 从完全探索（小查询）和部分探索（大查询）的搜索空间中学习

### 关键创新
1. **多任务学习**：联合预测基数、代价和最小代价
2. **自顶向下枚举**：避免穷举动态规划搜索
3. **图特定设计**：处理图数据库中的异构模式和复杂连接模式
4. **状态最小代价**：预测从任何中间状态可达到的最佳代价
5. **部分探索处理**：在训练期间区分完全和部分探索的查询

### 领域特异性
NeuSO 专为**图数据库**（子图匹配）设计，而非关系数据库。关键区别：
- 图查询涉及的连接比典型关系查询多得多
- 图数据库中的模式灵活性 vs 关系数据库中的固定模式
- 顶点匹配顺序优化 vs 连接顺序优化

## 对比分析

### 问题领域

| 优化器 | 目标领域 | 查询类型 | 优化目标 |
|--------|----------|----------|----------|
| **Neo** | 关系数据库 | SQL 查询 | 连接顺序、算子选择 |
| **Bao** | 关系数据库 | SQL 查询 | 为现有优化器选择提示 |
| **Lero** | 关系数据库 | SQL 查询 | 计划排序 |
| **NeuSO** | 图数据库 | 子图查询 | 顶点匹配顺序 |

### 学习范式

| 优化器 | 机器学习技术 | 学习类型 | 学习内容 |
|--------|--------------|----------|----------|
| **Neo** | 深度强化学习（值迭代） | 强化学习 | 计划生成策略 |
| **Bao** | Thompson 采样 | 强化学习（老虎机） | 提示选择策略 |
| **Lero** | 二元分类 | 监督学习 | 成对计划排序 |
| **NeuSO** | 多任务回归 | 监督学习 | 基数 + 代价估计 |

### 集成策略

| 优化器 | 集成方法 | 优化器替代 | 部署复杂度 |
|--------|----------|------------|------------|
| **Neo** | 完全替代 | 是 - 完全 | 高 |
| **Bao** | 基于提示的引导 | 否 - 增强 | 低 |
| **Lero** | 计划排序 | 否 - 增强 | 低 |
| **NeuSO** | 估计器 + 枚举器 | 是 - 完全 | 高 |

### 预测目标

| 优化器 | 预测内容 | 预测难度 |
|--------|----------|----------|
| **Neo** | 完整执行计划 | 高 - 复杂动作空间 |
| **Bao** | 最佳提示配置 | 中 - 离散动作空间 |
| **Lero** | 相对计划质量（A > B？） | 低 - 二元分类 |
| **NeuSO** | 基数 + 代价 + 最小代价 | 高 - 多任务回归 |

### 学习速度与数据需求

| 优化器 | 学习速度 | 数据需求 | 在线适应 |
|--------|----------|----------|----------|
| **Neo** | 慢 | 高 - 需要许多查询 | 是 - 持续 |
| **Bao** | 快 | 低 - 快速学习 | 是 - 持续 |
| **Lero** | 中 | 中 - 需要计划对 | 批量训练 |
| **NeuSO** | 中 | 中 - 需要标记的子查询 | 批量训练 |

## 关键架构差异

### 1. **替代 vs 增强**

**完全替代（Neo、NeuSO）：**
- 优点：可以学习全新的策略，不受现有优化器限制
- 缺点：失去数十年的工程积累，需要大量训练，部署风险高

**增强（Bao、Lero）：**
- 优点：保留现有优化器知识，部署更安全，学习更快
- 缺点：受现有优化器能力限制

### 2. **预测任务复杂度**

**最简单：Lero（二元分类）**
- "计划 A 比计划 B 好吗？" - 简单的是/否
- 对噪声和估计错误最鲁棒

**中等：Bao（离散选择）**
- "哪个提示配置最好？" - 分类选择
- Thompson 采样处理探索/利用

**最难：Neo（计划生成）和 NeuSO（多任务回归）**
- Neo：从头生成整个计划 - 巨大的动作空间
- NeuSO：同时预测多个连续值

### 3. **处理不确定性**

| 优化器 | 不确定性处理 |
|--------|--------------|
| **Neo** | 通过经验学习鲁棒性 |
| **Bao** | Thompson 采样通过探索自然处理不确定性 |
| **Lero** | 相对排序比绝对预测更鲁棒 |
| **NeuSO** | 多任务学习提供多个信号 |

## NeuSO 的独特贡献

### NeuSO 的不同之处？

1. **领域**：唯一为**图数据库**（子图匹配）设计的优化器
   - 其他针对关系 SQL 查询
   - 不同的优化问题：顶点匹配顺序 vs 连接顺序

2. **多任务学习**：联合预测三个相关量
   - 基数估计
   - 代价估计
   - 最小可达代价（新颖）

3. **状态最小代价**：预测从任何中间状态可达到的最优代价
   - 引导搜索朝向有希望的区域
   - 帮助早期剪枝无希望的路径

4. **自顶向下枚举**：避免穷举搜索
   - 传统 DP 探索所有状态
   - NeuSO 使用学习到的估计引导选择性探索

5. **部分探索训练**：区分完全 vs 部分探索查询的训练
   - 小查询：可以完全探索
   - 大查询：只能部分探索
   - 训练考虑这种差异

### 为什么 NeuSO 不能使用 Neo/Bao/Lero 的方法

**Neo 的方法不适合：**
- 图查询的搜索空间比关系查询大得多
- 子图匹配涉及更多连接
- 如此大的动作空间的强化学习不切实际

**Bao 的方法不适合：**
- 图数据库没有带提示系统的成熟优化器
- 基于提示的引导需要现有的优化器基础设施

**Lero 的方法可以部分工作：**
- 成对比较是适用的
- 但不能解决核心挑战：高效探索巨大的搜索空间
- NeuSO 的自顶向下枚举 + 最小代价预测更有针对性

## 对 ADL-OPT（DuckDB）的启示

基于 `docs/references/neuso-paper-summary.md` 中的现有总结，ADL-OPT 可以借鉴 NeuSO 的概念：

### 适用概念

1. **状态图视角（来自 NeuSO）**
   - 状态 = 已连接关系的集合
   - 转换 = 向连接添加一个关系
   - 连接图连通性约束有效转换
   - DuckDB 性能分析提供转换代价

2. **基数-代价图（CCG）框架**
   - 跟踪中间状态的基数和代价
   - 使用 DuckDB 的估计作为特征
   - 从性能分析收集实际代价

3. **探索策略**
   - 小查询：完全探索（枚举所有有效连接顺序）
   - 大查询：部分探索（采样有希望的路径）
   - 在训练期间区分这些

### 与 NeuSO 的差异

| 方面 | NeuSO | ADL-OPT v0 |
|------|-------|------------|
| **领域** | 图数据库子图匹配 | DuckDB 关系连接 |
| **输出** | 直接匹配顺序 | 离线 SQL 变体 |
| **编码器** | 查询图 GNN | 简单结构特征 + DuckDB 估计 |
| **部署** | 在线优化器替代 | 离线工件生成 |

### ADL-OPT 的推荐方法

**阶段 1（v0）：数据收集**
- 专注于类 CCG 的数据收集
- 从 DuckDB 性能分析生成转换标签
- 暂时不实现复杂编码器
- 使用简单特征：关系集、基数估计、连接图结构

**阶段 2：学习**
- 考虑 **Lero 风格的成对排序**（比 NeuSO 的回归更简单）
- 或者如果 DuckDB 暴露优化提示，使用 **Bao 风格的提示选择**
- 初期避免完全替代（Neo/NeuSO 风格）- 风险太高

**阶段 3：高级**
- 如果需要，探索 NeuSO 的多任务学习
- 为大查询实现自顶向下枚举
- 考虑用于搜索引导的最小代价预测

## 建议

### 对于关系数据库查询优化（如 DuckDB）

**从 Lero 或 Bao 方法开始：**

1. **Lero** 如果你想要：
   - 最简单的学习任务（二元分类）
   - 对估计错误最鲁棒
   - 对收集的数据进行批量训练
   - 非侵入式集成

2. **Bao** 如果你想要：
   - 快速在线学习
   - 持续适应
   - 基于提示的引导（需要提示基础设施）
   - 探索/利用平衡

**初期避免 Neo/NeuSO 完全替代：**
- 风险更高，更复杂
- 需要大量训练数据
- 失去现有优化器知识
- 更适合作为长期研究方向

### 对于图数据库查询优化

**NeuSO 是最先进的：**
- 专为子图匹配设计
- 高效处理大搜索空间
- 多任务学习提供鲁棒估计
- 自顶向下枚举避免穷举搜索

---

## 结论

四个优化器代表不同的哲学：

- **Neo**："用深度强化学习替代一切"
- **Bao**："用学习到的提示引导现有优化器"
- **Lero**："对计划排序而不是预测代价"
- **NeuSO**："预测多个信号并引导选择性搜索"

**对于 DuckDB 中的 ADL-OPT**，最实用的路径是：
1. 从**数据收集**开始（来自 NeuSO 的类 CCG 框架）
2. 实现 **Lero 风格的排序**（最简单的学习任务）
3. 如果 DuckDB 暴露提示机制，考虑 **Bao 风格的提示**
4. 将**完全替代**（Neo/NeuSO 风格）留给未来研究

**关键洞察：更简单的学习任务（排序 > 回归）和增强（引导 > 替代）导致更实用的系统。**
